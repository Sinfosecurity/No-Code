Fast Prototype Design Rules

"We are using a fast prototyping tool (VibeCoding / v0.dev) so you can SEE your idea instantly."

The 5 Rules

1

One screen first (Home screen only)

2

One main action (Add, Check-in, Report, Order)

3

Use real-looking sample content (5 items)

4

Big text + big buttons (easy for everyone)

5

Keep it tiny (no login, no payments, no “full system” today)

Think of It Like This

A prototype is a picture of your idea.

It helps people say “I get it!” in 10 seconds.

Today we focus on clarity, not complexity.

LASU 2001 Engineers • Build Without Coding STEP 4 • TEST 1:30 - 1:45

Testing Checklist

"Do 5 test actions: create, edit, filter, mark complete, re-open app."

The 5-Point Test

  • CREATE — Add a new task using the form. Does it appear in the list?
  • EDIT — Change a task's priority or category. Does it save?
  • FILTER — Try the different views. Do they show the right tasks?
  • MARK COMPLETE — Tap "Mark as Done". Does the status change?
  • RE-OPEN — Close and reopen the app. Is your data still there?

Common Issues & Fixes

  • Too much on one screen?
    Remove 50% of the text and keep 1 main button
  • Hard to read?
    Increase font size, spacing, and contrast
  • Confusing flow?
    Home → Add → Details (only)
  • Doesn't show the idea?
    Rewrite the prompt: user + problem + main action

LASU 2001 Engineers • Build Without Coding TIPS

Common Mistakes & Fixes

Mistake

  • Trying to build everything at once
  • Spending too long on design before it works
  • Too many screens and features
  • No real-looking sample content
  • Ignoring the mobile preview
  • Not testing each feature as you add it

Fix

  • Build the simplest version first (MVP)
  • Make it work, then make it pretty
  • Keep 3 screens and 1 main action
  • Add 5 realistic examples (names, dates, statuses)
  • Check mobile view after every change
  • Test one thing at a time — create, edit, delete

Remember: Your win is not the final design. Your win is the working prototype.
